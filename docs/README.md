# ドキュメント

KumiTypeの導入・フォント生成から、調整・検証・保守までの参照先を案内します。初めて使う場合はビルドガイドから読み進めてください。

[ドキュメント一覧](README.md) · [プロジェクトREADME](../README.md)

## 利用する

| 目的 | 文書 | わかること |
| --- | --- | --- |
| 環境を準備して生成する | [ビルドガイド](BUILDING.md) | OS別ツール導入、`uv`、単体・全数ビルド、オフライン利用、任意のDocker実行 |
| 入力フォントを管理する | [ソースフォント](FONT_SOURCES.md) | 配布元、固定版、可読ロックID、取得・更新・手動登録 |
| 見た目を調整する | [フォント調整](FONT_TUNING.md) | スケール、文字幅、ベースライン、半角カナ |
| 生成物を検証する | [検証ガイド](VALIDATION.md) | バイナリ、HarfBuzz、パッケージ監査、`G1`〜`G7` |
| リリースを準備・公開する | [リリース手順](RELEASING.md) | バージョン更新、候補版、draft確認、SHA-256・来歴証明 |
| 配布条件を確認する | [ライセンス](LICENSES.md) | 本体のMIT、フォントのOFL、著作権、Reserved Font Name |

## 設計・検証状況を知る

| 文書 | わかること |
| --- | --- |
| [アーキテクチャ](ARCHITECTURE.md) | 処理の流れ、モジュールの責務、キャッシュとマニフェスト |
| [検証状況と既知の制約](ACCEPTANCE_STATUS.md) | 全数検証の結果、確認範囲、未保証の事項 |
| [初期仕様書](SPECIFICATION.md) | 開発開始時点の設計意図（現行手順は各ガイドを参照） |

用語は[プロジェクトREADME](../README.md#生成できるフォント)で定義しています。Cascadiaの6種類を「ベース系列」、合成する日本語7種類を「日本語書体」、その組み合わせ42種類を「ファミリー」と呼びます。
